Markdown for LLMs — the field manual

MakeItMarkdown · updated July 2026 · the rules our converter follows, usable by hand too

Whether a converter produced it or you typed it, Markdown headed for a model's context window has one job: make the document's structure explicit in as few tokens as possible, without lying about what's missing. These are the ten rules we converged on building MakeItMarkdown — each one exists because we watched its absence break an answer.

The ten rules

  1. One H1, then a real hierarchy. The title is #, sections are ##, subsections ### — never skip levels, never fake a heading with bold text. Retrieval systems chunk on headings and models build their mental outline from them; a bolded paragraph is invisible to both.
  2. Tables are GFM pipes with a header row — always. A table without column names is a grid of orphaned numbers. Annotate types when they're ambiguous (revenue (float), signup_date (date)) so "1,204" and "45922" can't be misread as strings or serials.
  3. State truncation in the text itself. Showing the first 50 of 10,000 rows. A model told it has a sample summarizes a sample; a model not told invents the rest with full confidence. This single sentence prevents more hallucination than any prompt trick we know.
  4. Figures become named placeholders. [Figure: cell_12_figure_1.png] — one line that says a figure exists, where it sits, and what to call it. Never leave base64 in text meant for a model: one embedded screenshot can cost ~130,000 junk tokens.
  5. Fence all code, label the language, label outputs. ```python opens the model's code prior; **Output:** before result blocks keeps cause and effect apart. Truncate long outputs and say so (rule 3 applies to logs too).
  6. Give sections stable addresses when machines will point at them. For RAG or agent pipelines, add <a id="slug"></a> anchors and <!-- chunk: slug --> boundaries. Citations that survive re-indexing beat "page ~14".
  7. Front matter only when the destination reads it. Obsidian and archives want YAML (title, source, date); a chat paste wastes its first 15 tokens on it. Format for the destination, not from habit.
  8. Keep provenance one line long. Source: report-2026-q1.docx · converted 2026-07 near the top lets both humans and models answer "where is this from?" without a metadata block.
  9. Delete boilerplate, keep meaning. Navigation, cookie banners, repeated page headers, "12 of 96" — pure token tax. But never "compress" the actual prose: models quote what exists, and a paraphrased source is a corrupted source.
  10. Say what's missing. Scanned pages, dropped equations, unparsed sheets — one explicit line each. An honest gap gets worked around; a silent gap gets papered over with invented content. This is the converter's fidelity report in prose form.

Per-destination adjustments

DestinationWhat changes
Chat pasteToken-lean: outputs truncated hard, token estimate up top, no front matter
RAG / pipelinesChunk comments + stable anchors; keep tables whole inside sections
Obsidian vaultYAML front matter, callouts, ![[wikilink]] figures
Archive / citationFull front matter (authors, year, identifiers), faithful body, nothing truncated harder than the source forced

These four are exactly the converter's output presets — same detected structure, different discipline per destination.
